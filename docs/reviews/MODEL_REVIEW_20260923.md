# Recurrent calibration model review

검토 대상: 현재 `hand_transformer.py`, `hand_dataset.py`, 학습·평가·추론 CLI와 Colab 빌더. 모델 소스는 수정하지 않았습니다.

구조는 카메라별 GRU 상태와 누적 보정값 → 보정된 ray의 삼각측량·시간 외삽 → 카메라 융합 → 공간/시간 Transformer → 3D 잔차입니다. 기본 Gauss–Newton 반복은 0입니다. 보조 정답은 실제/명목 카메라 값으로 계산하며 forward 입력에는 사용하지 않습니다. 클립 단위 설치 오차를 여러 윈도우에서 추정하려는 방향은 적절합니다.

## 수정 우선순위

1. **[P1] 관측이 없는 구간의 보정 상태 갱신** — `hand_transformer.py:279`, `:334`. 모든 관측이 마스킹되어도 null token으로 GRU가 갱신되고 head의 increment가 params에 더해집니다. 제어 실험으로 출력 bias를 0.01로 설정한 뒤 완전히 빈 윈도우 10개를 넣었을 때 축별 회전 보정 벡터가 0.008727 rad, 위치가 0.01 world(0.3cm) 이동했습니다. 이는 학습된 모델의 실제 드리프트 측정이 아니라, 관측 없이 보정이 바뀌는 경로의 재현입니다. 전체 관측이 없을 때 상태를 보존하고 부분 카메라 누락 시 갱신 정책을 정해야 합니다.

2. **[P2] 패딩이 유효 데이터의 학습 가중치를 감소시킴** — `train_hand_transformer.py:44`. 무효 step의 손실을 0으로 만든 뒤 전체 K로 평균합니다. 같은 유효 윈도우 하나에 패딩 7개를 추가하자 loss가 0.0326413에서 0.00408016으로 정확히 1/8이 됐고 MPJPE는 같았습니다. 짧은 클립이 의도치 않게 약하게 학습됩니다. 유효 sample-step/관절 수를 기준으로 정규화해야 하며, 단순히 batch 전체의 유효 step 개수로 나누는 것만으로 서로 다른 길이의 샘플 가중치 문제가 모두 해결되지는 않습니다.

## 성능 판단 전에 필요한 검증

- 기본 학습·검증은 8개의 비중첩 윈도우(16프레임씩, 30Hz에서 약 4.3초)마다 상태를 초기화합니다. 추론 CLI는 최대 17개를 연속 실행합니다. 더 긴 세션에서 누적 보정값이 안정적인지는 현재 검증으로 알 수 없습니다. 전체 클립과 장시간 세션을 상태 유지하여 평가해야 합니다.
- 실시간 출력 주기를 정해야 합니다. 비중첩 16프레임 윈도우의 마지막 query만 사용하면 30Hz 입력에서 약 1.875Hz 출력입니다. 매 프레임 겹치는 윈도우로 state를 갱신하면 현재 학습과 달라지고 같은 관측을 반복 반영할 수 있습니다. 과거 프레임 출력을 한꺼번에 내보내면 그만큼 지연이 생깁니다. 상태 업데이트와 매 프레임 pose 추론을 분리하거나 실제 배포 주기로 학습·검증해야 합니다.
- baseline은 `HandWindows`, 모델은 `HandSequences`를 사용합니다. 선택된 query가 다르므로 두 MPJPE 차이를 모델 개선량으로 해석할 수 없습니다. 동일 query·mask·세션에서 비교해야 합니다. 최신 노트북은 참고값이라고 명시하고 있습니다.
- 최종 query는 도착한 과거 입력만 사용하지만 중간 프레임은 윈도우 전체에서 얻은 보정 상태를 공유합니다. 따라서 모든 출력 프레임이 엄밀히 causal한 것은 아닙니다. 배포의 최종 프레임 성능을 중심으로 평가해야 합니다.
- 데이터의 물리적 roll이 0이어도 월드축 회전 보정 벡터의 세 번째 성분이 0일 필요는 없습니다. 현재 보조 정답을 임의로 0으로 바꾸면 안 됩니다.

## 실행 확인

- 전체 단위 테스트 34개 통과.
- 기본 모델: **2,042,121 파라미터**.
- 이 PC CPU 2스레드, batch 1, 16프레임, 기본 구조, dropout 0/eval, 학습 전 가중치: warmup 후 4회 **39.3–42.3ms**. 데이터 생성이 병행 중인 간이 측정이며 Pi·GPU 속도로 일반화할 수 없습니다.
- 패딩/빈 관측 재현은 `.tools/review_recurrent_model.py`, 수치는 `.tools/recurrent_model_review.json`에 저장했습니다.
- 현재 새 아키텍처를 전체 데이터로 학습한 체크포인트의 일반화 정확도는 평가하지 않았습니다. 이전 아키텍처의 smoke 체크포인트를 새 모델의 성능으로 사용하지 않았습니다.

판정: 학습 실험을 시작할 구조는 갖췄지만, 패딩 정규화·빈 관측 상태 보존을 먼저 수정하고 장기 상태 및 실제 출력 주기를 검증한 뒤 실시간 배포 적합성을 판단해야 합니다.
