# HandLiteV3 전체 구조 — 기하 기준점·보정 신경망·배포

HandLiteV3는 비동기로 도착하는 카메라 3대의 2D 손 관절로 원하는 시각의 두 손 3D 관절 42개를 출력하는 기본 모델입니다(`--arch litev3`). 관절마다 최근 검출의 ray에 직선을 맞춰 삼각측량한 **기준점**을 만들고, **보정 신경망(corrector)**이 기준점에서의 보정값을 냅니다. 관절별 예상 오차와 손별 '시야 안' 확률도 출력합니다.

- 코드: [`hand_tracking/model.py`](../hand_tracking/model.py) (모델·스트림), [`runtime.py`](../hand_tracking/runtime.py) (NumPy 런타임), [`deploy.py`](../hand_tracking/deploy.py) (ncnn 내보내기)
- 설정: [`config.py`](../hand_tracking/config.py)의 `LiteV3Config`
- 비교용 모델: [HANDDIRECT_ARCHITECTURE.md](HANDDIRECT_ARCHITECTURE.md), 공통 입력·학습·명령: [MODELS.md](MODELS.md)

## 1. 이벤트 도착 시 (프레임마다 한 번)

관절별 u·v, ray 원점·방향, 촬영→도착 지연, 검출 여부 `[2,21,10]`를 손가락별 encoder(`layers.EventEncoder`, HandDirect와 같은 구조)에 넣어 손가락 토큰 10개(손 2 × 손가락 5) `[10,64]`를 만들어 저장합니다. 다른 카메라 프레임과 무관하게 한 번만 계산합니다.

## 2. query 시각 t마다: 기하 계산

학습 파라미터가 없고 float32로 계산하며 gradient가 흐르지 않습니다(`model.anchor_features`).

- **ray**: 카메라 3대 × 관절 42개마다, 그 관절이 검출된 최근 `fit_span_s`(0.2초) 안의 프레임들의 ray 방향에 시간에 대한 직선을 최소제곱으로 맞추고 t에서 읽습니다. 검출이 하나이거나 시간 간격이 너무 좁으면 평균을 씁니다.
- **삼각측량**: 관절마다 카메라별 ray로 최소제곱 삼각측량합니다(`geometry.triangulate`, ray 2개 이상, 카메라 앞, 평행하지 않을 때만 성공).
- **직전 위치**: t − k·`prior_step_s`(0.2초 간격, k = 1…5, `prior_span_s` 1.0초까지)에서 같은 직선 맞춤 + 삼각측량을 해서, 그 관절이 성공한 가장 최근 위치를 찾습니다. 맞춤 구간이 겹치지 않습니다.
- **지금 실패한 관절의 기준점**
  - 그 관절을 본 카메라가 있으면(`ray`): 보이는 ray 중 직전 위치에 가장 가까이 지나는 ray 위에서 직전 위치와 가장 가까운 점. 방향은 지금 관측에서, 깊이는 과거에서 옵니다.
  - 본 카메라가 없으면(`prior`): 직전 위치
  - 직전 위치도 없으면(`none`): 0. 보정 신경망이 위치 전체를 냅니다.

## 3. 보정 신경망 (corrector)

- **관절 토큰 입력 56개**
  - 관절 11개: 기준점 3, 기준점 − 직전 위치 3, 기준점 종류(삼각측량 / ray + 직전 깊이 / 직전 위치) 3, 직전 위치가 있는지 1, 직전 위치의 경과 시간 1
  - 카메라별 15개 × 3: 검출 여부, 기울기 사용 여부, 검출 수, 최신·가장 오래된 검출 경과 시간, 최신 u·v 2, ray와 기준점의 어긋남 3, 맞춘 ray와 최신 ray의 차이 3(맞춤이 과했는지), 직선에서 벗어난 정도 RMS·최신 검출(검출이 튀는지)
- 관절 토큰마다 MLP(56 → 64 → 64) + 관절별 학습 embedding
- 블록 × `blocks`(2): 카메라별 최근 8개 이벤트(0.5초 안)의 손가락 토큰 240개를 cross-attention(경과 시간 embedding, 빈 슬롯은 가림, null 토큰) → 양손 42개 관절끼리 self-attention → feed-forward
- 출력
  - 관절별 보정값 `[42,3]`. 마지막 층을 0으로 초기화해 학습 전에는 기준점 그대로입니다.
  - 예상 오차 `[42]`: log(1 + mm), 토큰 gradient를 끊은 별도 head(`error_estimate`)
  - 손별 '시야 안' logit `[2]`: 손의 관절 토큰 평균에서, gradient를 끊은 별도 head(`presence`)
- **최종 좌표 = 기준점 + 보정값**

## 4. 학습

- **손실**: 포즈(SmoothL1 β 6mm + 뼈 길이 0.1), 손목 기준 상대 좌표 1.0, 예상 오차 0.1, 시야 판정(BCE) 0.1. 시야 밖 손은 위치 손실이 없습니다.
- **로그**: epoch 줄의 `rel`(손 모양), `error_miss`(예상 오차가 실제에서 평균 몇 mm 빗나가는지), `in_view_acc`. 다음 줄 `kinds`는 기준점 종류별 비율 / MPJPE / (보정 전 기준점만의 오차)로, 괄호 안과의 차이가 보정 신경망의 효과입니다.
- **결과**(`event_litev3_state_tpu_e85_v3`, TPU v6e-1, 배치 128, lr 8.5e-4, 85 epoch; 관절 상태를 항상 더 최근 것으로 쓰던 때의 학습이지만, 학습에는 상태가 없어 이 수치는 그대로 유효): val 20.36mm. 평가(클립당 4윈도)에서 20.21mm, PCK@20mm 69.1%, 손목 기준 9.09mm, 참 월드 좌표 32.05mm, 시야 판정 99.0%, 예상 오차 빗나감 9.17mm.

| 기준점 종류 | 비율 | 최종 MPJPE | 보정 전 기준점 |
|---|---|---|---|
| 삼각측량 | 85.4% | 14.9mm | 44.8mm |
| ray + 직전 깊이 | 7.3% | 43.0mm | 112.7mm |
| 직전 위치 | 0.8% | 74.0mm | 147.2mm |
| 없음 | 6.6% | 57.9mm | — |

오차의 상당 부분이 삼각측량이 안 된 14.6%에서 나옵니다.

## 5. 스트림·배포와 관절 상태

- `LiteV3Stream`(PyTorch)과 `LiteV3Runtime`(NumPy + ncnn), 마스터 파이 C++ 런타임(`hand_tracker_master/src/litev3_runtime.*`, `--arch litev3`)은 이벤트가 오면 encoder를 한 번 돌리고, query 때 기하 계산과 corrector를 돌립니다. C++는 기하 계산을 double로 해서 Python과 같은 값을 냅니다.
- **관절 상태**: 두 스트림은 관절마다 마지막 삼각측량(점과 그때 쓴 최신 검출의 촬영 시각)을 기억합니다. 삼각측량이 성공할 때만 갱신하고, 모델 예측은 넣지 않습니다. 상태는 과거 창 탐색이 직전 위치를 못 찾은 관절에만 씁니다. 그래서 한 카메라에만 보이는 기간이 아무리 길어도 그 ray 위에서 마지막 깊이로 기준점을 잡습니다. 직전 위치의 경과 시간 입력은 학습 범위 끝(`max_prior_age_s`, 1.2초)으로 자릅니다.
- **학습과의 관계**: `forward()`(학습·평가)에는 상태가 없습니다. 과거 창 탐색이 모든 관절의 직전 위치를 찾는 동안에는 몇 번을 query해도 스트림과 `forward()`가 같습니다(테스트로 확인). 차이는 1.0초 넘게 삼각측량되지 않은 관절에서만 생기며, 학습에서는 그런 관절이 기준점 없음(`none`)이었던 자리입니다.
- **내보내기**: ncnn 그래프 2개(`encoder` 이벤트 도착 시, `corrector` query 시). 결과 폴더의 `litev3.json`에 설정과 그래프 입력 shape가 있습니다. `runtime.error_mm`(관절별 예상 오차 mm), `runtime.in_view_probability`(손별; 0.5 미만이면 그 손은 세 카메라 모두 밖), `runtime.anchor_kind`(기준점 종류)를 읽습니다.
- 연산량(ncnn 변환 기준): encoder 이벤트당 약 0.18M FLOPs, corrector query당 약 24.3M FLOPs.
